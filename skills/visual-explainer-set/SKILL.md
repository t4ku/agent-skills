# 図解セット（解剖図鑑）の作り方

題材を一次情報から調べ、目次（母艦）1 枚 + 章ページ 9〜14 枚の HTML 解説セットを作る。スライドではなく、図・操作できるデモ・ダイアログを多用した Web ページにする。ゴールは、読者が全体の地図を描け、要所を説明でき、次に読むものが分かること。

起動テンプレートと各項目の詳しい表は [references/meta-prompt.md](references/meta-prompt.md) にある。

## 1. 確認（1 回だけ）

埋まっていない項目だけを確認シートにまとめて 1 回で聞く。各項目に既定値（★）を付け、「おまかせ」ならそのまま進む。待つ間も下調べを始める。シートの最後に仮の章立て（ページ名 + 1 行の問い）を付ける。

- **A 題材・情報源・調査方法**：範囲（★全体）／版の固定（★今日の main のコミット）／方法 ①clone して読む ②公式資料 ③ブラウザで観察（通信・DOM・配信ファイル）④Web 検索（★リポジトリは①②、サービスは③②④）／除外（★なし）
- **B 対象レベル**：読者像（★実務のフルスタックエンジニア）／前提知識／持ち帰るもの（★全体像 + 自作のヒント）
- **C 出力**：形式（★目次 + 章の複数ページ。10 枚未満なら 1 ページ長編）／枚数（★目次 + 12〜14）／1 枚の分量（★図 2〜3 + 4〜6 節）／トーン（★設計図風）／インタラクティブ度（★半分以上のページに操作できる図）／言語（★日本語、識別子は原文）／公開（★非公開 Artifact）
- **D オプション**：学習 / QA / 深掘り / プロンプト生成 / 比較 / 更新追従 / 英語版 / スライド版

## 2. 調査

1. 版を固定（コミットハッシュ、または観察日時 + URL）し、全ページのフッターに出す。
2. 棚卸し：構成、パッケージ一覧、エントリポイント、公開 API・プロトコル、設定スキーマ、依存。数や名前は数えて確かめる。
3. 主要な流れを 3〜5 本、呼び出し関係でたどる（シーケンス図の材料）。
4. 主張ごとにタグ：`観察`（パス / URL 付き）／`資料`／`推測`（根拠 1 行）。
5. ドキュメントとコードの食い違いを拾い、どちらに合わせたか明記する。
6. 見えなかった範囲（別オリジン iframe など）は推測として書く。
7. 題材（共有データ・リポジトリ）は編集しない。

## 3. 構成

- 1 ページ = 1 つの問い。見出しは答えを含む形（例「承認ポリシー：いつ人間に聞き、いつ黙って実行するか」）。
- 並び：全体 → 部品の地図 → 中心ループ → シーケンス → 各サブシステム → 外部境界（API / SDK）→ 設計パターン・学び。
- 目次ページ：クリックで章へ飛べる全体図、章カード（番号・問い・難易度）、目的別の読み順 3〜4 本、版・方法・凡例。
- 先に `pages.json`（id, num, slug, title, short）を作る。

## 4. 制作

`<slug>-guide/` に `pages.json`、`style.css`（共通トークン + ダークモード）、`pages/NN.html`（本文断片）、`data/*.json`（大きな一覧）、`build.py`、`urls.json` を置く。`build.py` は `URL{NN}` を公開 URL に、`GH/` を固定コミットの blob URL に置換し、パンくず・ページャー（← 目次 / 次へ →）・出典フッターを付ける。

各ページの型：eyebrow（`07 · Approvals`）+ 答えを含む見出し + 3 行リード → 番号付き 3〜6 節 → 図 2〜3 → 根拠リンク → 「〇〇視点の学び」3 点 → ページャー。

図は問いの種類で選ぶ（飾りは作らない）：

| 問い | 図（操作） |
|---|---|
| 何でできているか | ブロック / レイヤー図（クリックで説明ダイアログ） |
| 部品と依存 | グリッド地図 / 依存グラフ（絞り込み） |
| 時間順の動き | シーケンス図（1 手ずつ再生） |
| 状態 | 状態遷移図 |
| 条件分岐 | 判定シミュレーター（実コードの関数を単純化して JS に移植し、出典明記） |
| 層の重なり | 積み重ね図（ON/OFF で最終値） |
| 守り | 入れ子図 |
| 大きな一覧 | 検索できる表 |
| 量 / 構文 / 出自 | 棒グラフ / ツリー / ベン図・比較表 |
| 規模感 / 衝突・再試行 | スライダーデモ / 時系列シミュレーター |

作法：インライン SVG か HTML/CSS で手書き。色は意味で分けて凡例を付ける（人＝橙、安全＝緑、拒否＝赤、システム＝青）。手で組んだ図は「細部省略」と書く。タグは図にも付ける。本文は最大 780px、図は最大 1080px、スマホ幅で横スクロールしない。ダイアログは `<dialog>` で Esc・キーボード対応。

## 5. 検証と公開

スマホ幅・ダークモードで全ページ確認 → 操作系が動くか確認 → 章ページを先に公開して URL を `urls.json` へ → 再ビルドして目次を最後に公開 → 全リンク確認。Artifact は非公開で出す。

## 6. 報告

1 行目に目次リンク。版と方法、章一覧、操作できる図のハイライト 3 つ、読むときの注意（推測範囲・見えなかった所・食い違い）、次の一手を 1 文。

## 7. オプション

- **学習**：章末クイズ 3 問、学習パスと進捗チェック、用語集
- **QA**：よくある疑問 15〜20 問を根拠付きで回答するページ
- **深掘り**：指定章を 4〜6 枚のサブセットに展開（同じ build / style、子目次）
- **プロンプト生成**：最終章に、最小クローン実装・自分のコードへの応用・前提入り質問・次の図解セット用のプロンプト集
- **比較**：類似題材と同じ観点・同じ図形式で並べる
- **更新追従**：固定版と最新の差分で、変わった章だけ更新して変更履歴を付ける
- **英語版 / スライド版**（スライドは要約のみ、本体は HTML）

## やらないこと

スライドを本体にしない（明示時を除く）。飾りの図を作らない。数・名前・版を推測で書かない。題材を変更しない。確認を何度も分けて聞かない。
